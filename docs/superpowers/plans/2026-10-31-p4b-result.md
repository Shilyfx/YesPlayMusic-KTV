# P4b 账号隔离最小实现结果

日期：2026-10-31

结果：实现完成；未提交、未部署。

## 实现

- `src/views/karaoke.vue` 将本地 `userId` getter 交给 `webRoomBridge`。桥接层只在本地比较身份；首次读取设为基准，身份变化（包括退出登录变为空值）才递增 `catalogEpoch`。open/exchange 仅增加整数 epoch，不序列化账号身份。身份 getter 抛错时沿用当前 epoch，不阻塞开房或心跳。
- `KaraokeWebHost` 接受可选的非负安全整数 epoch。epoch 改变时，在处理 `body.results` 前递增目录 generation、清理账号相关缓存并拒绝/移除旧 `catalog` pending commands。低于当前值的迟到请求以 HTTP 409 `STALE_CATALOG_EPOCH` 拒绝。
- `KaraokeCatalogService` 的目录、搜索曲目、歌曲详情、availability 与推荐/榜单 allowlist 写入均受 generation 保护。账号缓存与 promise 清除时保留 `localPlaylists` 在途请求、本地曲目索引和本地曲目缓存。新房间启动也会失效旧目录缓存。
- Host 将 epoch 同步到房间对象，`/ktv/api/state` 在根级可选返回非身份字段 `catalogEpoch`。远端页观察到 epoch 变化后清空搜索结果、用户歌单、推荐/榜单及曲目，递增各自请求 generation 并中止旧搜索；旧响应不能覆盖新目录。当前搜索、用户歌单或推荐/榜单模块立即重新加载。`localPlaylists`、播放 state 与互动数据不进入清理范围。
- 未增加本地列表 TTL 或分页；现有强制刷新竞态处理与 128 个目录、4096 个曲目、4096 个 availability 缓存上限保持通过。Axios 配置未修改。

## 隐私与兼容

- 身份值只在主屏桥接层用于比较；新增的身份相关传输字段只有整数 `catalogEpoch`，没有 UID、cookie 或账号 token。现有 host Bearer 鉴权保持原状。
- 旧客户端省略 epoch 时仍可开房、交换和确认命令。升级中的旧房间首次收到 epoch 会失效一次旧目录状态。
- 旧 state 响应省略 `catalogEpoch` 时远端页不触发清理，兼容旧 host；较低 epoch 不会回退远端 generation。公开 state 不包含 UID 或用户 ID。
- 账号切换时旧 catalog pending 以 `CATALOG_EPOCH_CHANGED` 拒绝并移出队列；其迟到结果不会确认新身份的命令。目录 API 中未识别的该错误按现有规则返回 HTTP 502 `REMOTE_UNAVAILABLE`，客户端显示通用稍后重试/手动刷新提示；availability 沿用现有 `error` 返回且不缓存。较低 epoch 的迟到 host exchange 返回 HTTP 409 `STALE_CATALOG_EPOCH`，桥接心跳在下一轮用当前 epoch 重试。登录状态不作为主屏开房或心跳前置条件。

- `node scripts/test-karaoke-web-bridge.js`：通过；覆盖同房间 A→B→ 退出、迟到 exchange 不执行旧命令、epoch 单调递增且请求体不含身份值。
- `node scripts/test-karaoke-web-host.js`：通过；覆盖无 epoch 的旧客户端、切换时清理旧 pending 与缓存、旧 epoch 请求拒绝及当前 epoch 确认。
- `node scripts/test-karaoke-catalog-performance.js`：通过；覆盖旧 promise 迟到不覆盖新身份的曲目/availability/目录/allowlist、本地曲目保留、强制刷新竞态及缓存容量上限。
- `node scripts/test-karaoke-remote-api.js`：通过；覆盖公共 state 提供整数 epoch、旧 room state 省略字段，以及公开结果不含用户身份字段。
- `node scripts/test-karaoke-remote-catalog-epoch.js`：通过；覆盖账号目录清空、请求 generation 递增、本地列表/播放 state/互动数据不变、重复/缺失/无效/回退 epoch 不触发失效。
