# LumaSing 代码整理计划

**目标**：让改点歌、改舞台和发版各自都有明确入口，并能独立验证和回退。本计划先做结构整理，涉及功能和配置行为的调整单独评审。

**技术范围**：Vue 主副屏、独立点歌页、Node 房间服务、Electron、软路由 Docker 与云端 Nginx。按任务依次验收，完成一批再进入下一批。

## 现状与优先级

- 当前工作区包含已部署的公网来宾功能、页面与部署文档修改，其中多项尚未入 Git。云端备案页脚也有独立配置。整理前要核对 Git、构建产物、软路由和云端四处的实际版本。
- 主屏 `src/views/karaoke.vue` 约 3,800 行，混合房间、投屏、队列、歌词和设置。最近实测中房间数据有公网链接，主屏面板却没显示；版本差异需要优先核实。
- 点歌页 `src/remote/main.js` 约 2,560 行，搜索、分页、轮询、应援、试听和 DOM 渲染集中在一起，修改其中一项容易影响其他流程。
- `src/electron/karaoke/KaraokeRemoteApi.js` 约 1,400 行，包含曲库、会话、限流、业务操作和路由。Docker 服务也使用该模块。`src/server/KaraokeWebHost.js` 约 1,500 行，同时处理主屏、来宾、副屏、文件和互动。
- `scripts/` 下约 87 个文件，包含自动化、浏览器验证、构建和部署。当前用法分散在 README、路由器运维文档、阶段项目书和进度记录中。

## 阶段 0：建立可回退的基线

- [ ] 审核当前未提交差异。将已部署功能按主题保存成可追踪提交，核实哪些源文件与线上产物对应。记录主屏与独立点歌页构建标识、服务端摘要、软路由 Compose 和公网 Nginx 配置版本。
- [ ] 核实主屏是否从正常入口显示两个二维码。若存在已上线版本缺口，将其单独修复和验收，避免把既有问题记为重构回归。
- [ ] 用现有测试记录房间生命周期、公网凭证、搜索/重试、分页、本地曲库、播放切换、多屏与应援基线。用 Ego 记录 Docker 主屏、副屏和来宾页的基准表现。
- [ ] 建立一页入口图，注明 Docker 主屏及副屏、Electron IPC、独立 `/room/`、公网 HTTPS 与隧道的关系。核对软路由备份是否足以恢复前端、服务端和配置，不动生产数据。

**验收**：能指出当前线上使用的版本，重现主要行为，并按记录回退到整理前状态。测试失败和既有差异有记录。

## 阶段 2：按用例拆分点歌页

- [ ] 在 `src/remote/` 先提取现有请求封装、状态轮询、搜索和分页逻辑。保持当前请求路径、取消规则、限流提示、缓存和分页行为。拆分期间保留独立入口 `main.js`。
- [ ] 再提取播放状态/队列渲染、试听与互动。保留当前选择器和 CSS；待模块归属明确后，按页面区域小批整理 `styles.css`。
- [ ] 将局域网和公网能力差异统一放到页面能力配置中，服务端继续负责权限判定。页面模块接收能力配置，避免再各自判断公网地址。

**验收**：两类入口能加入同一房间。搜索可快速换关键词，迟到的旧结果不会覆盖新结果。限流提示、分页加载、试听、队列和应援按入口正常工作。独立点歌产物可直接从软路由加载。

## 阶段 3：划清房间服务的责任

- [ ] 按现有类把 `KaraokeRemoteApi.js` 的曲库服务、会话/限流、请求路由分到各自模块。短期保留原文件导出，由 Docker 与 Electron 一起验收，再明确是否迁出 Electron 目录。
- [ ] 保留 `KaraokeWebHost` 作为 Docker 房间入口。先拆公网来宾路由、随后拆本地文件和副屏只读处理。将房间租约与主屏命令交换留在一个明确的生命周期模块，确保异步操作仍以房间代次校验。
- [ ] 用现有 API 测试对比状态码、返回结构和请求方法。重点核对公网与内网的会话边界、结束后旧凭证、私人歌单和主控限制，以及线上曲搜索后的限流恢复。

**验收**：Electron 和 Docker 共用同一套业务规则，主屏、来宾、副屏请求归属明确，已发布 URL 和会话行为保持兼容。

## 阶段 4：拆主副屏与播放器边界

- [x] 从 `src/views/karaoke.vue` 依次提取房间邀请面板、等待队列、本地曲库面板。组件接收视图数据并发出操作事件，由原页面负责协调。
- [ ] 在 `karaoke.vue` 与 `karaokeWeb.vue` 间，仅共享实际一致的显示和设置功能，保留主屏控制和副屏独立设置的各自职责。再按需要分离 `KaraokeControlPanel.vue` 的设置块。
- [ ] 最后核查播放与舞台生命周期。优先复用 `KaraokeManager`、`KaraokePlayerAdapter` 等已有边界。Folia、SmartBeat、主题渲染这一批先梳理接口，渲染逻辑或第三方产物改动另列任务。

**验收**：在线→本地→在线连续切歌有声，副屏能独立调整并跟随主屏，歌词同步、全屏、二维码、浅深色与应援能复测。
