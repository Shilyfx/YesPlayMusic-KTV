# P3 最小渲染去重结果

## 改动

- `KaraokePvScene` 按 runtime 记录暂停状态和最近一次暂停绘制的时钟位置。创建时的首帧绘制仍保留；相同暂停位置的后续更新不再重复调用 `setPaused` / `renderOnce`。暂停拖动到新位置、开始播放或重新暂停时仍同步并绘制。
- `newKaraokeBackgroundScene` 按 runtime 记录暂停状态。背景 `update(options)` 成功时同时记下其已应用的 `paused` 值，避免再调用一次 `setPaused`；背景外观仍逐次传给 runtime。
- 未改生命周期实现、Folia 原引擎、画质或后台资源加载策略。

## 计数证据

- 修复前运行新定向脚本时，创建首帧后重复调用 4 次暂停态 `updateTime()`，断言实际观察到 `setPaused` 从 1 次增至 5 次；原实现这 4 次也都经过无条件 `renderOnce()` 分支。
- 修复后，同一 4 次更新保持 `setPaused=1, renderOnce=1`。暂停 seek 后为 `1,2`；随后恢复再暂停后为 `3,3`，说明新位置和暂停切换仍会更新/绘制。
- 背景场景先设暂停一次，再执行 4 次主题变化和播放/暂停切换：显式 `setPaused=1`，renderer `update=6`；测试确认每个主题及 `paused` 值均到达 runtime，且 `staticMode=true` 保持开启。

## 核查

- `stageLifecycle` 已有候选取消、迟到 runtime 销毁及层清理；本轮没有重复改写。生命周期测试通过。
- `loadFoliaRuntime()` 只在函数调用时获取 manifest、样式和 runtime 模块。分析 worker URL 仅在 manifest 提供有效 worker 名称且调用 `createSmartBeatAnalyzer()` 时交给分析器；SmartBeat controller 仅在显式分析操作中创建 worker。逻辑已存在，本轮未重写。
- runtime 的 `prepared` 是以歌词 document 为弱键的 `WeakMap`；每个 document 的 `programs` 仅按有限渲染 mode 保存编译结果。本轮未发现无界缓存证据，未修改。
