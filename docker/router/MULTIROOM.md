# 公网多房间部署与更换（待联调）

此文描述隔离副本中的实现，不表示已上线。已有软路由单房间公网入口必须在新入口验证成功前继续保留。

- 云端网关使用 `src/multiroom/gateway-main.cjs` 和同目录 `gateway.cjs`，默认只监听云主机回环地址的 13102。`LUMASING_GATEWAY_CREDENTIALS_FILE` 指向云主机独立的 JSON 文件，内容为各主机 ID 与各自主机密钥的映射；不要把真实密钥提交到仓库、打进安装包或写进日志，Linux 上凭据文件须设为 0600。
- 现有 `ktv.shilyfx.icu` 的 HTTPS 站点可按 `/r/` 和 `/_gateway/` 分别反代到网关，其他路径继续指向原有单房间服务；配置前备份当前站点并运行配置检查。注意长轮询代理超时必须大于网关的轮询等待时间。
- Docker 可选设置 `KTV_MULTIROOM_GATEWAY_ORIGIN`、`KTV_MULTIROOM_HOST_ID` 和 `KTV_MULTIROOM_HOST_SECRET`。网关密钥仅在本机运行时注入。Mac 通过主机的公网点歌设置填写对应地址、主机 ID 与凭据，房间各自生成随机链接。
- 每台主机使用不同凭据；房间链接中的来宾令牌和主机凭据不同。勿将主机凭据分享给点歌来宾。
- 更换云主机：先在新主机部署相同网关及受保护的主机凭据、配置证书与反向代理，进行独立房间验证；保留旧站和旧隧道，DNS 切换后分别用公网及局域网验证。网关重启可能使活跃房间短暂不可用，不能假定期间请求不会丢失。
- 更换域名：先配置 DNS、证书和新站；在各主机设置新的网关地址，重新开场生成新链接；主机侧会校验网页请求的 Origin，旧链接不能自动继承新域名权限。
- 回退：先停止新房间并恢复原 Nginx 配置（测试通过后重载），停止新网关；软路由清除新增网关变量并恢复原部署文件及已验证的备份。不要覆盖音乐、账号或其他应用数据。

当前桌面版把主机密钥保存在本机应用配置中，并在设置界面隐藏；这不是系统钥匙串加密。应为每台设备使用单独的密钥，并限制该电脑账户对配置文件的访问。
